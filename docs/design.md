# Product and interaction decisions

The home page answers what DMZ MW4 is, identifies the announced Early Access date and gives a map-first entry alongside access instructions. It distinguishes Modern Warfare 4 from Call of Duty 4 (2007) and historical Warzone DMZ. Deep guides own map, weapon, mission and extraction intents instead of stacking a database on the homepage.

Visual direction: original dark tactical field notes, olive navigation and orange action accents. No copied logo asset or fabricated gameplay image. The video card uses the owner-supplied cover image unchanged; the embedded official video is credited separately because the supplied image timestamp is unverified. The abstract Hajin motif is decorative; the interactive location schematic warns that markers do not express geography, distance or exfil coordinates. Actual navigation belongs to the game map.

Shared navigation links to important routes. Dropdowns support hover, pointer travel into the menu, click, keyboard focus and Escape. Language links preserve the current topic. Weapon search and class filtering operate locally, expose a live result count and show a specific empty state. Mission cards describe types rather than fabricate unverified quest walkthroughs.

The video container, play button and iframe use the same full-width 16:9 dimensions. The player is created only on click, with a compact original YouTube link always available. Original video language and third-party processing are disclosed. A player load alone does not prove successful playback.

All six locales contain actual translated body text, labels, FAQs and policies. Proper names stay comparable to official sources. No native-speaker editorial review is claimed. Every public page supplies initial HTML, a single H1, canonical, reciprocal hreflang and links to the main navigation and support contact. Legal pages are noindex; a shared keyword homepage link uses the canonical absolute origin.

Six review perspectives informed implementation: player tasks drive routes; product scope excludes accounts and speculative live-map data; interaction design keeps core actions early; engineering reuses a shared renderer and configuration; new-player copy explains the name ambiguity; research boundaries distinguish announcements from tested results.

Routine updates must preserve that boundary and avoid promising faster or more comprehensive coverage than established sources can support. Page-level Search Console observations should use exact URL, comparable date ranges and explicit country/device filters. No indexing, query visibility or ranking claim follows from a build alone.
